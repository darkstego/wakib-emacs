# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Wakib Emacs is an Emacs starter kit built on [wakib-keys](https://github.com/darkstego/wakib-keys). It provides a "just works" Emacs configuration with common shortcuts (Ctrl+C/X/V/S etc.) instead of traditional Emacs bindings. Users install it by cloning into `~/.emacs.d`; packages auto-install from MELPA/ELPA on first launch. **Requires Emacs 30+** (init.el has a hard version gate).

## Validation Commands

There is no test framework. Validate changes with:

```sh
# Byte-compile everything with the real load-path (delete .elc after — never commit)
emacs --batch --init-directory . --eval '(package-initialize)' -L modules \
      -f batch-byte-compile early-init.el init.el modules/*.el
rm -f *.elc modules/*.elc

# Run the full config isolated from ~/.emacs.d (first run bootstraps packages
# into ./elpa, which is gitignored; subsequent runs measure warm startup)
emacs --init-directory .
```

Startup time: `M-x emacs-init-time`; target is well under 0.5s warm. Final verification is manual: launch Emacs and exercise the affected feature. `emacs --debug-init` re-enables all the warnings that early-init.el/init.el silence — use it when debugging startup issues.

For scripted assertions, run tty Emacs under `script -qec "emacs -nw --init-directory . -l testfile.el" /dev/null` with a `run-at-time` timer that writes results to a file and calls `kill-emacs`. Note `-l` counts as a command-line argument, so the no-arg `untitled`-buffer path is skipped; test that path with a temporary `user/init-user.el` instead (it must end in `(provide 'init-user)`, or the `require` fails and startup state is misleading).

## Branches and Status

- **`dev`** is the working branch — all changes land here first. It is the only branch carrying `CLAUDE.md` and `AGENTS.md`; these must never reach `master` (master is what users clone as their `~/.emacs.d`).
- **`master`** is the user-facing branch. The owner moves changes over from dev himself (currently as separate commits, so hashes differ between branches — compare content, not history, when checking sync).
- v2.0.0 (the Emacs 30+ redesign) is released. Since then: first-install warning silencing, a defaults/tuning sweep inspired by minimal-emacs.d, the 130x60 frame default, and org-mode scoping to startup/scratch buffers.
- Known open item: over ssh (no `COLORTERM=truecolor`) the modus-vivendi-tinted background `#0d0e1c` approximates to blue in 256-color terminals; a fallback to plain modus-vivendi for non-truecolor displays was planned but not implemented.

## Architecture

- **`early-init.el`** — loaded before the GUI and package system: frame settings (130x60 default size, no tool bar), startup speedups (GC deferral, `file-name-handler-alist` trick with restore-and-merge on `emacs-startup-hook`), warning silencing (native-comp and `*Warnings*` popups; `emacs --debug-init` un-silences everything), and a stray-`~/.emacs` check that errors with instructions if Emacs loaded `~/.emacs` instead of this directory.
- **`init.el`** — slim orchestrator: Emacs 30 version gate, package archives, load-path, then requires the five modules in order (order matters — `wakib-core` enables the wakib keymaps later modules attach bindings to), then `custom.el` and user overrides.
- **`modules/wakib-core.el`** — wakib-keys, CUA selection, undo (built-in `undo-redo` + vundo), better built-in defaults (savehist, recentf, save-place, electric-pair, scrolling, trash, auto-saves redirected into `auto-save/`...). Org-mode is deliberately scoped to the startup `untitled` buffer and `*scratch*` only — files with no recognizable mode must stay `fundamental-mode`.
- **`modules/wakib-ui.el`** — theme (built-in modus-vivendi-tinted), menu-bar items, which-key, ace-window.
- **`modules/wakib-completion.el`** — vertico/orderless/marginalia/consult/embark (minibuffer) + corfu/cape (in-buffer).
- **`modules/wakib-editing.el`** — avy, expand-region, multiple-cursors, yasnippet, flyspell-correct, org/markdown.
- **`modules/wakib-dev.el`** — magit, built-in project.el (plus a hand-built Project menu), eglot, treesit-auto, diff-hl, quickrun.
- **`refs/init-user.el.template`** — template for user-local config; useful-but-not-default settings live here (eglot auto-start, jinx, extra major modes, theme override).
- **`user/init-user.el`** — user-local overrides, loaded last via `(require 'init-user nil t)`. Gitignored; never modify or commit it.
- **`custom.el`** — auto-generated by Emacs customize. Gitignored; never commit it.

New packages go in the module matching their concern, as a `use-package` block under a `;; -------------------` section divider.

## Critical Constraint: Keybinding Policy

Wakib remaps the Emacs prefix keys: **C-c → C-d** and **C-x → C-e** (freeing C-c/C-x for copy/cut). When adding bindings:

- **Never bind to `C-c` or `C-x` prefixes** in new code (existing `define-key ... (kbd "C-x ...")` calls operate on the pre-remap map and appear to users under C-e — comment this when doing it deliberately, e.g. magit on `C-x g` shows as `C-e g`).
- **Alt** = navigation/selection/deletion and high-frequency commands; **Ctrl** = common shortcuts users expect; **C-e ?** = extended (old C-x); **C-d C-?** = mode-specific (old C-c, untouched); **C-d ?** (single char) = reserved for users — never populate.
- To override a Wakib binding, use `wakib-keys-overriding-map`; to remap a function everywhere, use `[remap fn]` on the relevant map. Completion popups follow the pattern `[remap wakib-next]`/`[remap wakib-previous]` (see corfu/vertico in wakib-completion.el).
- Menu-bar entries must display the Wakib key: use `:keys "C-e ..."` strings (see the Project menu in wakib-dev.el).
- `wakib-next-more`/`wakib-previous-more` are wakib-keys' documented extension hooks; override them with `advice-add :override` (see the flyspell integration in wakib-editing.el).

## Conventions and Gotchas

- Every `.el` file starts with `;; -*- lexical-binding: t -*-`; modules end with `(provide 'wakib-<name>)`.
- `(require 'use-package-ensure)` in init.el is **required** before the first `use-package` call: Emacs 30's bundled use-package only honors `use-package-always-ensure` once that library is loaded, otherwise early packages silently fail to install.
- Built-in packages configured via use-package need `:ensure nil` (which-key, eglot, editorconfig).
- Prefer `:defer t`/`:hook`/`:bind`/`:mode` per package; do not set `use-package-always-defer`. Keys bound in `wakib-keys-overriding-map` must be bound in `:init` (not `:bind :map`, which defers until the package loads and breaks autoloading).
- Guard optional features: `(require 'feature nil t)`, `(bound-and-true-p mode)`.
- Emacs default Lisp indentation (tabs in this repo's elisp); mark outstanding work with `;; TODO`.
