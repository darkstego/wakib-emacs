# Wakib Emacs - Agent Guidelines

## Project Overview

This is a **Wakib Emacs starter kit** — an Emacs configuration repository built on top of the [wakib-keys](https://github.com/darkstego/wakib-keys) project. It aims to provide a modern, user-friendly Emacs setup that "just works" out of the box. **Requires Emacs 30+.**

## Structure

- **`early-init.el`** — Frame settings and GC deferral only; loaded before the GUI and package system.
- **`init.el`** — Slim orchestrator: version gate, package archives, load-path, module requires, custom-file, user overrides.
- **`modules/`** — The actual configuration, one file per concern, each providing `wakib-<name>`:
  - `wakib-core.el` — wakib-keys, CUA selection, undo, built-in sensible defaults
  - `wakib-ui.el` — theme, menu bar, which-key, window switching
  - `wakib-completion.el` — vertico/orderless/marginalia/consult/embark + corfu/cape
  - `wakib-editing.el` — avy, multiple-cursors, expand-region, snippets, spelling, org/markdown
  - `wakib-dev.el` — magit, project.el, eglot, tree-sitter, diff-hl, quickrun
- **`refs/`** — Reference files. `refs/init-user.el.template` is the template for user-local overrides.
- **`user/`** — User-local directory (gitignored). Place personal overrides in `user/init-user.el`.
- **`custom.el`** — Auto-generated by Emacs (`custom-set-variables`). Not tracked in git.

Module load order in init.el matters: `wakib-core` enables the wakib keymaps that later modules attach bindings to.

## Build / Run / Test

This is an Emacs configuration — there are no traditional build, lint, or test commands.

- **Byte-compile check** (with real load-path; never commit `.elc`):
  `emacs --batch --init-directory . --eval '(package-initialize)' -L modules -f batch-byte-compile early-init.el init.el modules/*.el && rm -f *.elc modules/*.elc`
- **Isolated run**: `emacs --init-directory .` runs the config without touching `~/.emacs.d`; the first run bootstraps packages into `./elpa` (gitignored).
- **Startup time**: `M-x emacs-init-time`; target well under 0.5s warm.
- **No test framework**: validate changes by loading Emacs and manually testing the affected features.

## Code Style Guidelines

### File Headers

Every `.el` file must start with a lexical binding declaration:

```elisp
;; -*- lexical-binding: t -*-
```

Modules end with `(provide 'wakib-<name>)`.

### Comments and Section Dividers

- Use `;;` for comments and section divider blocks for logical groupings:

```elisp
;; -------------------
;; Package Name
;; -------------------
```

- Use `;; TODO` for outstanding tasks.

### use-package Conventions

All third-party packages use `use-package`. Follow the established style:

```elisp
(use-package package-name
  :defer t                  ; defer loading when possible
  :diminish mode-name       ; hide mode name in mode line
  :hook (mode . minor-mode) ; hooks go before config/bind
  :init
  ;; runs immediately — bindings into wakib-keys-overriding-map go here
  :config
  ;; runtime config — runs on first load
  :bind (("key" . command)))
```

- `:defer t`, `:hook`, `:bind` or `:mode` for packages that don't need immediate loading.
- Built-in packages (which-key, eglot, editorconfig) need `:ensure nil`.
- Keys bound into `wakib-keys-overriding-map` go in `:init` with `define-key`, **not** `:bind (:map ...)` — the latter defers the binding until the package loads, which breaks autoloading.
- `(require 'use-package-ensure)` in init.el must stay before the first `use-package`: Emacs 30's bundled use-package only honors `use-package-always-ensure` once that library is loaded.

### Naming Conventions

- Functions and variables: `kebab-case`.
- Custom functions in this config are prefixed with `wakib-` (internal helpers `wakib--`).

### Keybinding Policy

- Do **not** use `C-c` or `C-x` prefix keys in new bindings — Wakib remaps these to `C-d` and `C-e`. Deliberate `(kbd "C-x ...")` bindings display as `C-e ...` and should carry a comment (e.g. magit).
- Override wakib keys via `wakib-keys-overriding-map`; remap functions via `[remap fn]`.
- Completion UIs get `[remap wakib-next]`/`[remap wakib-previous]` entries (see corfu/vertico).
- Menu-bar items must show wakib keys via `:keys "C-e ..."` strings (see the Project menu in wakib-dev.el).
- `C-d` + single character is reserved for users — never populate it.

### Error Handling and Safety

- Use `(require 'feature nil t)` for optional features and `(bound-and-true-p var)` for variables of possibly-unloaded packages.
- Use `advice-add` rather than function redefinition (see the `wakib-next-more` flyspell override).

### What to Avoid

- Do **not** modify `user/init-user.el` — it is gitignored and belongs to the end user.
- Do **not** commit `custom.el`, `elpa/`, or any `.elc` byte-compiled files.

## Adding New Packages

1. Add a `use-package` block to the module matching the package's concern, under a clearly labeled section divider.
2. Defer loading (`:defer`/`:hook`/`:bind`/`:mode`) unless the package must load at startup.
3. Document any non-obvious configuration choices in comments.
4. If the package introduces new keybindings, follow the keybinding policy above.
5. If a setting is useful but not a good default, put it (commented out) in `refs/init-user.el.template` instead.
